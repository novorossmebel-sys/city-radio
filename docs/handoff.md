## 1. Что это и цели

**Продукт:** автоматизированное городское медиа — «радио в мессенджере» для **MAX + Telegram**.
По распис* «программа дня» авто-публикуются: погода, курс валют, гороскоп, рецепты, здоровье/польза,
юмор, местные новости, пробки — по каждому крупному городу РФ.

**Ключевые решения по продукту:**
- **Ставка на MAX (first-mover):** ~85 млн DAU, рост на господдержке, ниша городских медиа там пустая. Telegram — второй контур.
- **Полная автоматизация** (по требованию владельца) → полупассив после сборки.
- **MVP — один город (Новороссийск)**, движок city-agnostic → тираж = добавление конфига города.
- **Каденс = «программа дня»** (утро/день/вечер/ночь), НЕ спам раз в 1–2 ч — главный приём против отписок.
- **Бюджет до 1 млн ₽.** Т.к. разработку делаем сами, dev-затраты ≈ 0 → почти весь бюджет идёт на разгон аудитории.

**Бизнес-контекст (как пришли к идее):** был актив — помещение 135 м² на территории завода (нет клиентского
трафика), отопление +24 °C, потолки 3 м, аренда 55 000 ₽/мес, Новороссийск. Перебрали много бизнесов
(раки-УЗВ, кофе-обжарка, грибы, 3D-печать) — каждый проверяли Вордстатом, большинство отклонили. Главный вывод:
**поисковый спрос локально почти нулевой, поиск — не мотор.** Отвязались от помещения → ушли в онлайн/контент →
пришли к city-radio. Отдельная задача: **пересдать/закрыть аренду 55к**, чтобы она не съедала прибыль.

## 2. Текущее состояние кода (что уже работает)

Вертикальный срез собран и проверён живым смоук-тестом (модуль валют тянет реальные данные ЦБ).

```
city-radio/
├── run.py            # CLI: post <module> [city] | serve
├── engine.py         # модуль → пост → все публикаторы
├── scheduler.py      # «программа дня» (APScheduler), пока упрощённая
├── config.py         # .env + города
├── cities.yaml       # Новороссийск (добавить город = блок здесь)
├── content/
│   ├── base.py       # интерфейс ContentModule → Post(text, image?, parse_mode)
│   ├── currency.py   # ✅ курс валют ЦБ РФ (без ключей)
│   └── weather.py    # ✅ погода OpenWeather (нужен бесплатный ключ)
├── publishers/
│   ├── base.py       # интерфейс Publisher
│   ├── telegram.py   # ✅ Telegram Bot API (sendMessage/sendPhoto)
│   └── max.py        # ✅ MAX Bot API (реализован; нужна проверка на живом токене)
├── requirements.txt  # requests, apscheduler, python-dotenv, pyyaml
├── .env.example      # TELEGRAM_BOT_TOKEN, MAX_BOT_TOKEN, OPENWEATHER_API_KEY
└── docs/
    ├── plan_city_radio.md   # полный план проекта
    └── handoff.md           # этот файл
```

**Расширяемость:** новый контент-модуль = класс в `content/` + строка в `engine.py`→`MODULES`;
новая платформа = публикатор в `publishers/` + запись в `PUBLISHERS`; новый город = блок в `cities.yaml`.

**Запуск:**
```bash
pip install -r requirements.txt
cp .env.example .env   # вписать токены
python run.py post currency     # тест: один пост сейчас
python run.py serve             # планировщик (программа дня)
```

## 3. Боты и API — найденные решения

### Telegram (готов)
- Bot API зрелый. Токен у **@BotFather**. Бот — **админ канала**.
- Методы `sendMessage` / `sendPhoto`, чистый HTTP (без библиотек).
- Реализован в `publishers/telegram.py`; без токена/канала тихо пропускается.

### MAX (реализован; требует финальной проверки)
- **Bot API у MAX ЕСТЬ, боты умеют постить в каналы** — главный техриск снят в плюс.
- Токен у **@MasterBot** → команда `/create` (ник 11–60 символов, окончание `_bot`).
- Метод: `POST /messages?chat_id=<id>`, тело `{"text": "...", "format": "html"|"markdown"}`, лимит 4000 символов, 30 req/s.
- Бот должен быть **админом канала**; `chat_id` канала — числовой.
- **Две точки неопределённости** (вторичные источники расходятся) — вынесены в константы наверху `publishers/max.py`:
  1. базовый URL: `platform-api.max.ru` **или** `platform-api2.max.ru`;
  2. авторизация: заголовок `Authorization: <token>` **или** `Authorization: Bearer <token>`
     (передача токена через query-параметр `access_token` объявлена устаревшей).
  → При первом реальном посте: если 401/403/404 — поменять константу. Оф. дока: **dev.max.ru/docs**.
- Картинки в MAX требуют предзагрузки (upload → token → attachment) — пока не реализовано, шлём текст.

### Общая архитектура
Единый **контент-движок → интерфейс Publisher → обе платформы**. Один пост генерится один раз и уходит и в Telegram, и в MAX.

## 5. Ключевые решения и выводы (короткая память проекта)

- **Поиск — не мотор** ни локально, ни федерально (доказано Вордстатом по кофе/3D и т.д.).
- **Моат контент-проекта** = локальный живой слой (новости/пробки/события) + first-mover на MAX; авто-филлер (погода/гороскоп) сам по себе не защищён.
- **Сначала 1 город**, доказать юнит-экономику, потом тираж (метрика go/no-go).
- **Юр. осторожность с новостями:** только белый список источников + рерайт со ссылкой; ЧП без верификации не автопостим;
  каналы 10k+ — регистрация в РКН; закон о фейках; здоровье — только общие советы + дисклеймер; финансы — факт из ЦБ, без советов.
- **MAX-ставка** оправдана: 85 млн DAU, господдержка, пустая ниша городских медиа.
