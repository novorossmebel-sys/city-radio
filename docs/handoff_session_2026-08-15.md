## 1. VK как источник — закрыли тему полностью

Пытались получить `VK_API_TOKEN` для двух рубрик (Юмор, Новороссийск сегодня): создали Standalone-приложение в VK ID, но просмотр самих ключей доступа требует **подтверждения профиля** (верификация аккаунта на стороне VK) — уткнулись в это и решили не проходить.

Проверили альтернативу — чтение открытых страниц VK без токена, просто HTTP-запросом: не работает, VK — полноценное JS-приложение (SPA), без авторизации сервер отдаёт только пустой HTML-каркас, текста постов там нет ни в десктопной, ни в мобильной версии.

**Решение:** отказались от VK целиком. Обе рубрики переведены на Telegram-каналы:
- Юмор/мемы города: `@leoday`, `@memachh`, `@mudak` (ротация)
- Новороссийск сегодня: `@novorosstoday`, `@first_nvrsk` (ротация)

Заодно нашли и подтвердили реальные каналы для ещё двух рубрик, у которых раньше были плейсхолдеры/пусто:
- Кино и сериалы: добавили 11 Telegram-каналов (`@kinopoisk`, `@remizorro`, `@movies_filmy` и др.) к уже бывшим web-источникам
- Еда и рецепты: 8 Telegram-каналов (`@blog_andychef`, `@tveda`, `@foodrumedia` и др.) вместо `source: null`
- Кино (сеансы): `kinomonitor.ru` — сеть кинотеатров «Монитор»

`VkGroupSource` в `content/news.py` оставлен в коде нетронутым — вдруг понадобится позже, но прямо сейчас ни одна рубрика его не использует.

## 2. `my.telegram.org` сломан — обошли через официальные ключи Telegram Desktop

**Что обнаружили:** форма «Create application» на my.telegram.org стабильно выдаёт пустой попап «ERROR» без деталей. Перепробовали: 2 номера телефона (разные страны), 2+ браузера, инкогнито, VPN (несколько стран, в т.ч. Дания) и без VPN, отключённый блокировщик рекламы, разные варианты Platform/Short name. Проверили аккаунты через официального `@SpamBot` — оба чистые, без ограничений. Нашли открытый issue на GitHub (`tdlib/telegram-bot-api#597`) с идентичными симптомами у другого человека, закрытый как «not planned» — то есть это известный нерешённый баг на стороне сервиса, не наша проблема и не то, что можно починить настройками браузера.

**Решение:** `config.py` теперь по умолчанию подставляет **официальные `api_id`/`api_hash` самого Telegram Desktop** (`2040` / `b18441a1ff607e10a989891a5462e627`) — они открыты, потому что Telegram Desktop сам open-source и эти значения зашиты в его публичном репозитории. Это полностью в обход my.telegram.org. Если `TELETHON_API_ID`/`TELETHON_API_HASH` заданы в `.env` — используются они, иначе — эти дефолты.

`telethon_login.py` — одноразовый двухшаговый вход (`request` → `confirm <код> [<пароль>]`, среда не поддерживает интерактивный `input()`). Залогинились номером-наблюдателем (+45..., Дания, отдельно от основного аккаунта пользователя), сессия сохранена в `telethon_observer.session` (gitignored). **Живой тест прошёл**: `TelegramChannelSource('novosti_efir').fetch()` вернул реальные посты с заголовками и ссылками.

**Живые публикации сегодня:**
- Курс валют — опубликован в реальный Telegram (MAX пропущен — токена ещё нет).
- ~15 черновиков прогнано через модерацию из разных рубрик (происшествия, здоровье, еда, кино, юмор, городские новости) — часть одобрена и опубликована, часть отклонена (сработала авто-ротация на следующий источник).

**Важный нюанс по `cities.yaml`:** Telegram-адрес оказался **приватной группой**, а не каналом-трансляцией (Bot API вернул `"type": "group"`). В группе все участники могут писать, в отличие от канала, где только админы публикуют. Решение владельца: пока оставить группу как есть, для теста разницы не критично; для реального запуска стоит перейти на настоящий канал.

## 4. Баги, найденные и исправленные по ходу живого теста

Всё найдено буквально по скриншотам реальной публикации в группу — не гипотетически:

1. **«Источник» показывал сырой необрезанный текст** оригинального поста вместо короткой подписи → добавлено `RawItem.source_label` (например `@blog_andychef`), используется во всех адаптерах.
2. **Рерайт урезал текст до 2-5 предложений** — по факту это не соответствовало ожиданиям владельца → системный промпт переписан на полный пересказ своими словами без урезания.
3. **В финальном посте не было рубрики** — только заголовок и текст → добавлена строка рубрики в начало поста.
4. **Не было способа скрыть ссылку на источник** → кнопка-переключатель, по умолчанию источник скрыт.
5. **Кнопки «Отклонить»/«Опубликовать» не убирали сообщение** — оставались висеть в чате → теперь сообщение удаляется сразу после нажатия.
6. **Сбой авто-продолжения ронял весь бот-процесс** — один таймаут YandexGPT во время авто-подбора следующего поста (после отклонения) убивал `poll_forever()` целиком, бот переставал отвечать на все кнопки → обёрнуто в `try/except` на уровне отдельного апдейта и отдельно на уровне авто-продолжения.

## 6. Известные ограничения/риски на заметку

- Очередь модерации теперь переживает перезапуск бота (`moderation_state.json`), но состояние ротации (`rotation_state.json`) и обе персистентности — простые JSON-файлы без блокировок; при двух одновременно запущенных процессах модерации возможна гонка записи (не встречалось на практике, но теоретически возможно).
- `api.telegram.org`, `my.telegram.org`, иногда и другие внешние хосты (`cbr-xml-daily.ru`, `llm.api.cloud.yandex.net`) периодически отдают таймауты локально — не всегда воспроизводимо, обычно помогает просто повторить запрос; для продакшена (VPS) этот класс проблем должен исчезнуть.
- Telegram-группа `radio_max_nvrssk` приватная — реальных подписчиков там нет, только владелец.
- YandexGPT всё ещё может добавить деталь, которой нет в оригинале (например, один раз дописал «в Новороссийске» туда, где источник вообще не называл город), не помечая `needs_manual_review` — фактчекинг перед публикацией остаётся на владельце.
